# DeepIntern — 高校实习全流程管理系统

## 700 个账号的性能验证与发布记录（2026-10-02～06）

使用规模为约 700 个总账号、通常少量同时在线。本节记录本次优化的实测范围及发布门槛，不能作为“已通过 700 人并发验收”的结论。

### 本次代码优化

- 前端保留登录后的角色首页预加载，取消访客启动时下载全部管理页面；构建恢复按动态导入自动分块。
- 学生申请、学生面试和企业申请列表的直录取标记改为按学生/岗位去重、每批最多 200 对读取；仍按 `COALESCE(update_time, create_time) DESC, id DESC` 选择最新记录，不缓存业务状态。N 次数据库往返降为 `ceil(有效去重键数 / 200)` 次，数据库内部仍需查找每对键的最新记录。
- 企业岗位数量改用相同企业条件的 `COUNT(*)`，避免加载岗位详情及剩余名额统计。
- 健康检查即使在连接验证异常时也归还连接；保持原接口响应结构。
- `LOG_TOTAL_SIZE_CAP` 默认 `1GB`，限制诊断日志滚动历史，保留原 30 天留存、单文件 10MB 轮转。当前文件和异步清理可能使占用暂时超出该值；数据库审计及备份归档不受此配置管理。

## 📖 项目简介

DeepIntern 是一套面向高等院校的**实习全生命周期管理平台**，覆盖学生从找实习、投递申请、实习过程记录、反思报告提交，到教师审核评分、企业招聘管理、数据统计分析等全部环节。系统支持四种角色协同作业，并通过 **DeepSeek 大模型** 深度集成 AI 能力，实现智能评分、实习报告分析、岗位描述生成等特色功能。

## 🤖 AI 功能概览

侧边栏采用 **LangGraph 业务 Agent**：独立 Python 私有执行服务负责原生工具循环、检查点与追问恢复，Java 后端负责当前登录身份、四端权限、导入校验、操作确认和不可重复执行的业务回执。集成的是业务执行服务和框架库；不会把整个 OpenCode 开发工具嵌入业务系统。模型继续使用管理端设置的默认模型与参数，供应商密钥只保留在 Java 后端。

Python 服务使用 Python 3.13、`backend/agent-runtime/requirements.lock.txt` 的固定依赖和 PostgreSQL 检查点存储。只运行一个 Uvicorn worker；多个 worker 尚无分布式执行权协调，不能直接扩容。管理员显式执行 `python -m deepintern_runtime.initialize` 初始化检查点表，初始化连接仅提供给该命令；正常执行账号只拥有已初始化表的 SELECT/INSERT/UPDATE/DELETE，启动时不执行 DDL，也不回退到内存或 SQLite。完整启动说明见 [执行服务说明](backend/agent-runtime/README.md)。

| 配置 | 设置位置与要求 |
|------|----------------|
| `AGENT_HARNESS=langgraph` | Java；部署时显式指定，避免旧基线配置仍选择 OpenCode |
| `AGENT_LANGGRAPH_URL` | Java；执行服务的私网固定地址，例如 `http://agent-runtime:8791` |
| `AGENT_LANGGRAPH_SERVICE_KEY` / `AGENT_RUNTIME_SERVICE_KEY` | Java / Python；两端相同、随机且至少 32 字符，不写入源码、前端或对话状态 |
| `AGENT_RUNTIME_POSTGRES_DSN` | Python；独立检查点库的 CRUD 账号连接，通过受保护的运行环境注入 |
| `AGENT_BRIDGE_BIND_ADDRESS` | Java；跨容器时绑定内部网卡或容器内部 `0.0.0.0`，默认本机回环不能供另一容器访问 |
| `AGENT_BRIDGE_TOOL_PORT` / `AGENT_BRIDGE_MODEL_PORT` | Java；私网固定端口，例如 `18971` / `18972`；使用完整属性对应的环境变量，兼容未替换配置资源的发布包 |
| `AGENT_BRIDGE_TOOL_URL` / `AGENT_BRIDGE_MODEL_URL` | Java；Python 可达的完整地址，例如 `http://backend:18971/tools` / `http://backend:18972/model/v1` |
| `AGENT_IMPORT_PRIVATE_DIR` | Java；独立私有持久卷，例如 `/app/agent-private/imports`，必须与公共上传目录分开 |

Java、Python 和 PostgreSQL 通过明确的私有网络连接；执行服务和两个 Java 网关端口均不发布到公网或浏览器。每轮 Java 下发独立模型/工具租约，执行工具时重新核对身份、能力、任务状态和业务范围；取消与结束会撤销租约。私有服务认证、供应商密钥和租约均不存入客户端响应或检查点元数据。部署需要同时保留检查点数据库、Java 聊天/动作回执表和私有附件卷；普通 HTTP 健康检查不能代替完整对话与业务确认验收。

运行时故障会明确返回错误；不会静默切换底座。需要回退时，由运维显式设置 `AGENT_HARNESS=opencode`，仍需在实际 Java 容器中保留 Node.js 22 及固定官方 OpenCode 1.18.35（`npm install -g opencode-ai@1.18.35`），并配置对应可执行文件与私有工作目录。旧 OpenCode 会话保留为历史；LangGraph 建立自己的检查点线程，不将旧框架的待答问题直接反序列化为新任务。`AGENT_HARNESS=legacy` 仍为显式旧问答模式。OpenCode 回归测试 `OpenCodeHarnessRuntimeTest` 需设置 `AGENT_OPENCODE_TEST_EXECUTABLE` / `AGENT_OPENCODE_TEST_NODE`，使用隔离模拟模型；未配置时跳过。

管理员在侧边栏上传 Excel 后直接说明导入要求。Agent 分页读取源表、匹配真实班级专业并校验，缺失或冲突信息在聊天中追问；反问、新查询和修改要求由同一会话理解。校验后展示数量与问题位置，只有针对当前预览明确确认才导入，更正后必须重新确认；已有账号、密码与历史不覆盖。原始 Excel 私有保存并记录 SHA-256，来源、导入选项、当前预览和确认状态保存在 `agent_import_workspace`，不再仅依赖 Redis 24 小时上下文。管理员须显式执行 `backend/src/main/resources/db/migration/V20261012_01__agent_import_workspaces.sql`；MySQL 业务账号仍只有 CRUD。旧 Redis 工作区在归属校验后按需迁移；历史上传未保留原始文件的事实不会被补造。部署迁移时先停止旧 Redis 写入实例。新建账号初始凭据仍通过独立鉴权入口查看，不进入模型上下文。

## 🔐 安全机制

- **JWT 认证**：无状态 Token 认证，支持 Access Token + Refresh Token 双令牌机制
- **角色权限**：基于 RBAC 的细粒度权限控制，路由级 + 按钮级双重校验
- **Spring Security**：全链路安全拦截，自定义认证入口和权限拒绝处理
- **密码加密**：BCrypt 哈希存储
- **CORS 跨域**：白名单策略
- **操作日志**：AOP 切面自动记录关键操作，管理员可审计
- **数据库账号分离**：业务账号无 DDL 权限，物理隔离

管理员日志中心（`/admin/logs`）分为操作日志、登录日志和安全事件。今日概览按分类查看权限返回；列表 IP 脱敏，详情及导出的敏感字段受 `log:sensitive:view` 控制。查询默认最近 7 天、跨度最多 365 天、分页最多 100 条；导出使用已应用筛选，最多 100,000 条，并记录导出结果。详情可按请求 ID 检索关联记录。

留存默认普通操作及安全事件 180 天、登录日志 180 天、高风险操作及安全事件 365 天；可设置 30～3650 天，高风险期限不得短于普通期限。手动清理需预览、填写原因并确认，与每天 02:30 的定时清理使用相同路径；高风险操作及安全事件成功归档后才清理在线记录，归档保存在 `backup.path/audit-archive`，由 `audit.retention.archiveDays` 管理归档期限（默认 730 天）。非法留存配置会阻止清理。普通到期记录不做归档。

完整性报告区分通过、内容或签名异常、连续性无法完整验证、无可校验数据。留存清理造成的前驱缺失、历史未签名记录及缺少签名根都不能视为完整通过，应结合归档与清理审计核查。旧的按条数删除、全量清空及独立清理器已停用；后端发布时须停止旧实例后执行干净构建，避免残留旧清理器类。

统一 Agent 架构、交互、能力授权与验收标准见 `backend/src/main/resources/docs/AGENT_DESIGN.md`。阶段六发布、功能开关、固定时间调度语义和回退步骤见
`backend/src/main/resources/docs/PHASE6_RELEASE.md`。

AI 页面操作直接读取当前身份的菜单入口、路由关联的表单清单及已打开表单的字段结构。新增页面使用 `agentPage` 关联原组件与 `SUBMIT_FORMS`，菜单保留 `data-agent-route`；只为打开表单的按钮添加 `data-agent-open`，不要给保存、删除或提交按钮添加此标记。AI 只选择当前可用入口，原页面权限及校验继续生效，写入表单后仍由用户保存或提交。

企业基础信息页面与 AI 查询共用 `backend/src/main/resources/agent/company-info-schema.json` 中的字段、选项和标签定义；调整这些定义时修改同一来源，不另维护 AI 专用解释副本。查询工具按当前登录企业读取最新已保存资料，不将历史回答当作当前数据，未登记的标签含义保持未知。

AI 执行边界：`my_permissions.availableQueries` 从当前角色的实际工具定义生成，包含参数结构，不维护第二份能力列表。每次查询（含重复查询缓存命中）重新核对工具授权；分页结果提供 `returnedCount`、`hasMore` 和有后续页时的 `nextPage`，本页条数不代替总数。模型返回的页面目标必须在当次候选中，填表另验 `form_fill` 权限；同一账号同时只处理一个页面意图请求，当前进程最多并发八个，多实例部署还需网关限流。

页面执行等待实际入口稳定，检查页面、表单实例、身份与会话变化，取消后不继续操作；循环选择和未完成填表不能回报为成功。新增安全入口必须只打开页面或表单，不得绑定业务提交；正式写操作沿用服务端确认、对象归属与幂等校验。浏览器故障回归：设置本地测试账号 `E2E_PW_COMPANY`（可选 `E2E_COMPANY`、`E2E_BASE_URL`），在 `frontend` 执行 `npx playwright test --config=playwright.harness.config.ts`。这些测试使用受控模型响应验证取消、切页、关闭、循环与输入竞态，不能替代真实模型验收。

1. `backend/src/main/resources/db/migration/V20260920_01__agent_history_actions.sql`
2. `backend/src/main/resources/db/migration/V20260920_02__agent_notification_guard.sql`
3. `backend/src/main/resources/db/migration/V20260920_03__teacher_task_runs.sql`

迁移新增会话、草稿、消息版本对应的生成任务、时间线事件、请求幂等记录、动作回执、通知占用和调度运行记录。第二个迁移的 `ALTER` 语句须逐列核对后执行，只补缺失列；配置值改为 `TEXT` 以容纳完整角色及通知策略。业务账号仍仅需 SELECT/INSERT/UPDATE/DELETE，不授予 DDL 权限。Redis 只用于限流和短时协调，不保存唯一历史或成功凭证。

回退时先关闭 AI 能力入口并暂停教师自动跟进，再恢复兼容的旧代码。保留新增表、列、聊天、动作回执及通知占用，尤其不能清空 `PENDING` / `UNKNOWN` 记录来重试通知。确认结果需核对真实业务/邮件服务记录；回退不撤销已提交业务或已发送通知。需要恢复备份时应另行制定并确认数据恢复范围，不直接覆盖迁移后的业务数据。

百炼实时语音使用浏览器 AudioWorklet 采集单声道 16 kHz PCM，经鉴权 WebSocket 转接；服务端环境变量为 `BAILIAN_ASR_API_KEY`，`agent.voice.allowed-origins` 必须配置实际前端来源。默认不保存原始音频。未配置密钥时明确提示不可用，文字输入保留。停止录音会等待尾句转写并保留可编辑文字，用户明确发送后才解析填表。

登记的 59 个表单使用统一的实例、字段版本、原表单校验与批次撤销机制。保存范围分别为：57 个接入原服务端业务结果，面试信息模板保存到当前浏览器，实习去向登记目前仅为本页草稿（原页面没有后端提交接口）。回执必须来自对应请求明确成功的分支，填写记录本身不能证明已保存；修改过的旧值、否定修改指令和未明确授权的覆盖会保留。清空也须明确指定字段。

### AI 业务查询与权限边界

AI 查询由服务端登录身份、角色工具白名单和记录归属共同限制；页面上下文、模型参数、用户自称身份均不能授予权限。每次工具调用前后重新检查账号、对话能力与教师范围，撤权或负责范围改变即中止当前任务。

| 查询 | 数据来源与边界 |
| --- | --- |
| 统一实习时间 | 教师统一日历，起止日期、鉴定截止和心得周期；不从个人记录推断 |
| 学生岗位申请 | 登录学生的岗位申请记录单独计数，不混入普通申请、面试、确认 |
| 学生基本资料 | 本人姓名、学号、年级、学院、系、专业、班级、联系方式是否已填写；缺项明确标记，不用旧文本推测组织归属 |
| 学生当前实习与历史 | 复用业务状态派生服务，按 currentFlag 区分经历；不从历史 Offer 推测正在实习，不使用个人起止日期替代统一安排 |
| 综合学生顾问背景 | 按需合并本人资料、负责辅导员、当前实习、待办及统一日历；不自动逐项复述背景 |
| 学生负责老师 | 本人班级实际关联的有效辅导员，只返回当前姓名和身份；未关联班级与无有效关联分别说明 |
| 学生心得 | 本人期数、截止和真实提交状态；不输出全文、联系方式或其他学生数据 |
| 学生鉴定 | 本人已有鉴定状态、附件数量、退回意见；只读查询不创建草稿，不暴露附件地址 |
| 学生进度、待办与计划 | 本人真实业务记录，普通申请、Offer、确认、当前经历分别表达 |
| 教师待办、心得与简报 | 辅导员负责班级、系教师本系、学院教师本学院；空范围不扩大；历史范围再次校验 |
| 企业岗位、申请与确认 | 企业 ID 取登录身份；指定岗位必须属于本企业 |
| 管理员概览与企业审核队列 | 现有管理端只读投影，不开放任意 SQL 或任意个人资料查询 |

知识解释不能作为个人状态证据。关键本人提交状态、岗位申请数量和统一日期需要对应的本轮成功查询；查询异常终止回答，不转换成零条记录。只有成功查询确无记录才可说当前范围未查到，配置字段确实为空才可说尚未设置。未接入查询必须明确说明暂不支持，不能声称系统没有该功能。本清单是已接入边界，不代表所有业务页面的所有字段都已接入 AI。

本地只读数据范围集成测试：设置 `DEEPINTERN_LOCAL_READ_QA=true`、`DEEPINTERN_DB_URL` 为本机 MySQL URL、`DEEPINTERN_DB_PASSWORD` 为业务账号密码后运行 `mvn -Dtest=AgentReadScopeLocalTest test`。测试只允许 `127.0.0.1:3306/internship`，不执行 DDL 或业务写入。


### AI 运行容量配置

聊天模型入口共享单个后端进程的容量限制，默认最多同时调用 8 路、每分钟 120 次调用尝试；填表同一账号同时只处理 1 次、每分钟最多 10 次。繁忙时明确提示稍后重试。普通模型调用连接超时 10 秒、读取超时 40 秒，不自动重试；流式调用最多 90 秒。ASR 使用语音模块自身限额，模型连通性探针独立执行。

以下配置可在服务器配置中覆盖，也可通过 Spring 环境变量绑定，例如 `AI_RUNTIME_MAXCONCURRENTCALLS` 和 `AI_RUNTIME_MAXREQUESTSPERMINUTE`（属性中的短横线应删除）。上线时应根据实际 API 套餐额度调整，默认值不代表供应商允许的额度，也不构成日费用硬上限。

```yaml
ai:
  runtime:
    max-concurrent-calls: 8
    max-requests-per-minute: 120
    max-user-requests-per-minute: 10
    connect-timeout-millis: 10000
    read-timeout-millis: 40000
    stream-timeout-millis: 90000
    agent-workers: 4
    agent-queue-capacity: 16
    agent-queue-timeout-millis: 30000
    agent-task-timeout-millis: 90000
    stream-auth-refresh-millis: 2000
    title-queue-capacity: 16
  reflection:
    workers: 2
    queue-capacity: 64
    retry-delay-seconds: 60
    recovery-initial-delay-ms: 10000
    recovery-delay-ms: 30000
```

心得提交成功后才启动后台分析；队列满、服务器重启或 API 暂时不可用时，保留已提交的心得，由后台扫描恢复。每个提交版本最多记录 3 次分析失败，间隔至少 60 秒；耗尽后可由教师人工批阅或手动重新分析。撤回、重交或人工批阅后的旧分析结果不写回。已保存的人工评分（包括未发布成绩及零分）会停止自动分析；教师保存与 AI 写回共用心得行锁。AI 退回草稿同时结束原提交记录，允许学生修改重交。无效 JSON、缺失评分或不合法分数按分析失败处理，不生成零分成功记录。此机制复用现有心得和进度记录表，无需新增表结构。

上述并发和去重规则按单后端实例生效；多个实例会叠加额度，需要在网关或共享协调层设置总额度。700 个注册用户不等于 700 路 AI 并发，正式容量仍需结合高峰请求量、供应商限额及服务器实测确认。
